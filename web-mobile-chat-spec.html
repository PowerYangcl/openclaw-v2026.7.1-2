  • apple-touch-icon.png 必须保留：manifest.webmanifest 的 icons 是空数组（对齐 ui），它是 iOS「添加到主屏幕」唯一的图标来源。

3.3 网关与 CSP 边界（结论：不用改网关）

  • 静态资产白名单已经就位：CONTROL_UI_ROOT_PUBLIC_ASSETS 恰好就是这 6 个名字 —— apple-touch-icon.png / favicon-32.png / favicon.ico / favicon.svg / manifest.webmanifest / sw.js， 且网关会把 href="/<name>" 重写成带 base path 的形式。 src/gateway/control-ui.ts:172-183
  • MIME / 后缀已支持：.webmanifest 在静态资源后缀表里 src/gateway/control-ui.ts:170。
  • CSP 允许同源 SW：策略里已有 worker-src 'self' src/gateway/control-ui-csp.ts:70，无需为 PWA 放宽任何指令。
  • 文件名必须完全一致：这是唯一硬约束 —— 换成 manifest.json 或 service-worker.js 都会落到 SPA fallback / 404 上。
  • 不需要 service worker 的 scope 特权头：sw.js 在站点根（或 base path 根）， 默认 scope 已覆盖应用。
文档层面已有先例：docs/web/web-replacement-plan.md:177 早前把 「web 不带 SW、若引入 PWA 需评估 CSP 兼容」列为待评估项。本次核实结论是 CSP 不构成阻碍（worker-src 'self' 已在策略内），该顾虑可以关闭； 建议实现后同步更新这一行。

标签条；窄屏窗格头回归（chrome="pane"）+ 拆分按钮开关；触控/字号/短横屏/元信息常显。

验收：① 窄屏只有一个窗格可见；② 标签条出现、可横向滚动、不溢出视口； ③ 点第二个标签 → 内容切换 + 路由 session 同步 + 另一窗格运行态不受影响（注入同一 chat 广播帧验证）；④ 窗格头与输入区均无拆分按钮；⑤ 放大回宽屏后恢复双窗格与分隔条。

06 · 仍需拍板的 4 个细节

细节选项默认（按此实现）影响
① 窄屏是否保留窗格头 A（对齐 ui）：保留窗格头（会话下拉 + 关闭），标签条在其上方 ⇒ 顶部两行 chrome； B（省一行）：窄屏不渲染窗格头，把「关闭」放到标签条内，会话切换靠侧栏目录 A —— 与 ui 行为一致，且窄屏仍能直接换会话 B 可省约 36–40px 垂直空间
② manifest 是否补安装图标 A（对齐 ui）：icons: []，仅 iOS 用 apple-touch-icon； B（补齐）：新增 192/512 PNG 并写入 icons A —— ui 现状就是空的，先对齐；B 需额外产出图标资源 B 影响 Android 安装体验
③ 登录页是否纳入 A：只做「不横向溢出 + 输入框可点」的最低兜底； B：按对话页标准完整适配 A —— 符合「仅对话页」的范围约定 B 增加 1 文件 / 约 100 行
④ manifest 主题色 A（对齐 ui）：#0a0a0a（深色启动背景，避免闪白）； B：改成与 web 主题一致的浅色 A —— 深色启动底色对浅色应用同样不突兀，且与 ui 完全一致 仅影响启动瞬间的背景
建议顺序 先落 P0（外壳 + PWA）：它是 ①③ 的共同前提，且与上述 4 个细节全部无关 （4 个细节都只影响 P1/P2 或资产细节），可以先做完再逐个确认，不会返工。
